# R5 Final Auction 구현 및 검증 보고

2026-10-06 · 기준 커밋 `e2e56d16ca515aedf44b60e78c0061e715f68fa8` · 제공된 `PORENA_R5_FINAL_AUCTION_SPEC_FINAL.md` 적용.

## 규칙과 호환성

R4 결과 → 추가 수입 없이 `FINAL_AUCTION` → 1회 정산 → 낙찰이 있으면 3초 공개 → `FINAL_LOADOUT` → 4인 승률 프리뷰 → 공용 보드 5장 쇼다운 → 최종 결과. R1~R4, 가격표, 족보 점수, 순위 점수, 최종 점수 공식과 BB ICM은 유지한다.

- 정상 풀: 4×5장 OWNED + 32장 AVAILABLE. 모든 상점 예약을 해제한다. 최대 8장 낙찰 후에도 카드 52장 원장을 유지한다.
- 기본 40초, 마지막 3초 유효 입찰만 now+3초 연장, 최대 55초. 조기 종료 없음. 첫 입찰은 기본가, 경쟁은 +5BB 이상 정수. 최대 2장, 철회·자기 레이즈 불가.
- BB는 예약만 하고 정산 때 한 번 차감한다. 낙찰자가 드러나는 시점은 정산 이후다. 본인 예약금·슬롯·추월 알림은 본인에게만 투영한다.
- 출전 5장은 전원 확정 전 비공개. 정확히 5장 보유 시 자동 확정, 그 외 30초 만료 시 가장 강한 독립 5장(동률이면 R4 카드 우선). 미출전 카드는 OWNED 유지, BLOCK으로 표시한다.
- 기존 R5 진행 저장 방은 `finalAuction` 부재를 기준으로 기존 상점·7장·무보드 규칙을 끝까지 유지한다. 신규 R5 진입부터 새 규칙을 적용하며 자산 마이그레이션은 하지 않는다.
- 카드 부족 생존자는 기존 몰수패 처리. 임의 카드 지급 없음. 비정상 풀은 실제 AVAILABLE 전체를 사용하고 poolWarning에 수를 기록한다.

## 서버·AI·승률

온라인은 기존 Durable Object 직렬 처리와 WebSocket rate limit을 사용한다. 새로운 action 3개: `FINAL_AUCTION_BID`, `FINAL_LOADOUT`, `LOCK_FINAL_LOADOUT`. alarm이 경매·봇·정산·출전 만료를 진행한다. 재접속으로 마감이나 낙찰 공개 시간이 리셋되지 않는다.

봇은 익명 최고가, 공개된 모든 보유 카드, 자신의 예약 정보만 받는다. 기존 `scoreBotPlan`으로 카드 시너지/예상 족보/승률/잔액을 평가하고, 제한된 BLOCK 가치를 더해 상한 가격을 산정한다. 최초 행동은 2초+좌석별 2.7초로 분산하고 추월 반응은 중앙 상수 900~2200ms를 쓴다. 즉시 맞입찰하지 않는다.

4인 승률은 서버에서 공개 카드 집합을 정렬한 독립 시드로 240개 보드를 샘플링한다. 출전·BLOCK 포함 모든 OWNED를 제외하고 동률은 1/N을 나눈다. 실제 RNG/미래 보드를 사용하지 않는다. Node 집중 테스트에서 초기 측정 약 1.6ms(환경 및 동시 부하에 따라 변동). 실제 모바일 기기 CPU 측정은 수행하지 않았고 클라이언트는 서버 수치를 표시한다.
