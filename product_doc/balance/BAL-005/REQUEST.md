# BAL-005 — R3 Omaha / R4 5장 사전 승률 계산 기준 검증

상태: 분석 요청 준비 / 사용자 승인 대기
분석 기준 코드 커밋: `c7b2315` (승인된 rank 2/3/4 가격 변경 포함)
분석 브랜치: `balance/BAL-005-latest`

## 분석 목적

게임 시작 전 표시되는 두 플레이어의 예상 승률이 R1 Hold'em에서는 납득 가능하지만, R3 Omaha 4장과 R4 5장에서는 가끔 실제 카드 강도와 맞지 않는다는 사용자 관찰이 있다. 승률은 확률 추정치이므로 완전한 정답을 요구하지 않되, 어떤 카드·보드·상대 분포·보드 런·무승부 처리·반올림을 기준으로 하는지 명확히 하고 현재 표시값과 실제 규칙의 일치 여부를 검증한다.

## 검증 대상

- R1: 2장 vs 2장 Hold'em 기준선을 유지하고 비교 검증한다.
- R3: 4장 vs 4장 Omaha. 실제 판정의 정확히 2장 홀카드 + 3장 보드 제약, 두 게임/보드 런, 독립 보드 여부를 확인한다.
- R4: 5장 vs 5장 Best Five. 실제 매치의 보드 수, 홀카드와 보드의 조합, 5장 선택 규칙을 확인한다.
- R5: 보드 없는 7장 비교는 별도 기준선으로 확인하되, 이번 핵심 범위는 R3/R4다.

## 검증 질문과 가설

1. `showdownEquity`와 봇의 `scoreBotPlan`이 R3에서 동일한 Omaha 제약을 적용하는가?
2. 실제 R3가 두 런을 사용한다면 사전 승률도 두 독립 보드 결과를 같은 방식으로 합산하는가? 한 보드만 샘플링하거나 두 런의 승률을 단순 평균하지 않는 오류가 있는가?
3. R4의 5장 핸드가 실제 엔진의 `findBestFive` 결과와 동일한가? 보유 카드와 상대 카드를 제외한 덱, 보드 5장, 중복 카드 금지가 적용되는가?
4. 상대 카드가 고정·무작위·현재 참가자 카드 제외 중 어떤 분포로 생성되는가? 사용자가 보고 있는 상대 핸드와 계산에 사용한 상대 핸드가 일치하는가?
5. 승리/패배/무승부를 1/0/0.5로 처리하는가? 두 플레이어 합계가 항상 100%가 되는가?
6. R3/R4의 샘플 수가 오차 범위를 설명하기에 충분한가? 동일 seed로 반복할 때 표시값이 안정적인가?
7. 정수 반올림이 작은 차이를 과장하거나 숨기는가? UI에 `예상 승률`만 표시할 때 표본 수·오차 범위를 오해할 가능성이 있는가?
8. 의심 사례를 카드 강도 오류, 표본오차, 실제 규칙과 계산 규칙 불일치, 표시/반올림 문제로 분류할 수 있는가?

사전 가설(확정 사실 아님): R3는 두 보드 런과 Omaha 조합 제약을 UI 계산이 충분히 반영하지 못할 가능성이 있고, R4는 5장 조합 자체보다 낮은 샘플 수와 정수 반올림이 체감 불일치의 원인일 수 있다. 반드시 코드·재현 사례로 확인한다.

## 관련 실제 경로

- `holto-chess/src/ui/showdownEquity.ts` — UI 사전 승률 샘플링, 라운드별 표본 수, 보드 생성, 반올림
- `holto-chess/src/ui/ShowdownPrepPanel.tsx` — 승률 표시와 대상 플레이어 매핑
- `holto-chess/src/ui/showdownEquity.test.ts` — 현재 승률 회귀 테스트
- `holto-chess/src/game/botStrategy.ts` — 봇 구매 계획용 `scoreHeadsUp`, R3/R4 규칙 모델과 샘플링
- `holto-chess/src/game/engine.ts` — 실제 R3/R4 보드·핸드 판정 및 런 구조
- `holto-chess/src/core/poker/evaluate.ts` — `findBestFive`, `findBestOmaha`, `compareHands`
- `holto-chess/src/core/poker/cards.ts` — 덱 구성과 카드 ID

## 비교·재현 설계

- 기준 핸드 세트: 강한/약한 Omaha 구조, 중복 rank, suitedness, connectedness, AAxx, 낮은 카드·높은 카드, R4 made hand/드로우/산개 핸드를 포함한다.
- 각 사례에서 실제 엔진 판정과 UI 함수 결과를 같은 남은 덱·같은 상대 분포로 비교한다.
- 가능한 경우 전수 계산 또는 충분한 Monte Carlo 반복을 사용하고, 계산 비용 때문에 샘플링하면 표준오차·95% CI·seed를 함께 기록한다.
- R3는 두 독립 보드 런의 매치 승률(런별 승/무/패와 최종 매치 결과)을 별도로 보고한다.
- R4는 보드 5장과 5장 선택 결과를 기준으로 보고하며, 실제 규칙상 보드 수가 하나인지 확인한다.
- 동일 입력의 반복 실행에서 결과가 같은지, 다른 seed에서 CI 안에 있는 변동인지, 상대 카드 분포가 바뀌어도 방향이 유지되는지 확인한다.
