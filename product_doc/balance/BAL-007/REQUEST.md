## 목적 및 사용자 관찰

사용자 요청: R2에서도 프리플랍 승률을 계산해야 한다. 현재 최신 커밋에서 R2 매칭 로딩 화면은 RUN 1과 RUN 2 카드를 분리하여 각 RUN 승률을 표시한다. 이 분리 승률의 규칙·산식·실행 흐름이 실제 R2 규칙과 맞는지, 오류나 오해 소지가 있는지 검토하고 신뢰할 수 있는 계산 기준을 제안한다.

관찰은 승률 표기가 구현되어 있다는 점뿐이다. 잘못된 승률, 규칙 불일치 또는 사용자 체감 사례는 아직 측정·재현되지 않았으므로 결함으로 확정하지 않는다.

## 검증할 질문과 가설

1. UI가 각 RUN의 대표 카드+보조 카드 조합을 엔진과 똑같이 선택하는가? 현재 규칙은 대표 카드 1장을 두 RUN에 공통 사용하고 각기 다른 보조 카드 한 장을 사용한다.
2. 각 RUN의 계산에서 양측 전체 보유 6장을 dead card로 제외하는가? 실제 엔진은 해당 두 참가자의 보유 카드를 제외하고 한 셔플 덱에서 서로 겹치지 않는 보드 2개를 뽑는다.
3. 한 RUN의 주변 승률을 독립적으로 계산하는 방식이 맞는가? 동일한 46장 후보 덱에서 각 5장 보드를 균등 표집하면 각 RUN의 주변 분포는 같을 수 있지만, 두 RUN의 결과는 보드 비중복 때문에 종속된다. 화면이 “RUN별 보드 승률”인지, 2개 RUN 전체 매치 승률/포인트 기대값인지를 명확히 분리한다.
4. 무승부를 0.5승으로 계산하고 반올림하는 것이 목표 지표와 일치하는가? 실제 각 RUN은 승리/스플릿별 BB·Point 및 streak 효과가 있으며, 합산 매치에서 두 승의 조합은 단일 승률과 다른 지표다.
5. 현재 표본 수·시드·반올림의 정확도와 안정성은 어떠한가? 전수 계산, 재현 가능한 Monte Carlo, 혹은 둘의 혼합 중 현실적 방식을 비교하고 오차/신뢰구간을 제시한다.
6. 카드 순서·좌석 순서를 바꾸어도 같은 결과가 나오는가? 같은 고정 카드 케이스에 대한 반복 재현성, 좌우 교환 대칭성, 카드 중복/불완전 입력의 처리와 UI 자리표시자를 검증한다.
7. 사용자가 보고 싶은 것은 RUN별 보드 승률뿐인가, 아니면 2판 합산 승리·승점/BB 기대값인가? REPORT에서 지표별 정의와 표시 라벨 권고안을 제시하되 UX나 밸런스 변경을 직접 구현하지 않는다.

## 분석 대상 및 현행 규칙(기준 커밋에서 재확인)

- 모드: PORENA 최신 구현, 규칙 버전 2의 R2 RUN IT TWICE.
- 각 참가자는 카드 3장을 소유하고 대표 1장과 RUN별 보조 카드 1장씩을 구성한다. 각 RUN은 2장 홀카드와 5장 보드로 최선의 5장을 비교한다.
- R2 각 매치는 두 참가자의 전체 소유 카드 6장을 제외한 encounter-local 덱을 만들고, 한 덱에서 5장 보드 2개를 순서대로 뽑아 카드 중복 없이 처리한다.
- 두 보드는 각 RUN의 결과와 포상을 따로 결정한다. 현행 값은 `ROUND_POINTS.r2Run.win=4`, `split=2`; BB/streak 보상은 엔진 공통 ledger 경로에서 각각 처리된다. 요청자는 규칙 변경을 승인하지 않았다.
- 요청서 작성 시점의 UI는 RUN별 `showdownEquity(2, runLeft, runRight, allSixOwnedCards)`를 호출한다. 함수는 R2당 1200개 표본, 보드당 5장 샘플, 보드 동률 0.5-share, 정수 퍼센트 반올림을 사용하며 두 좌석의 값은 합계 100으로 구성한다. 정확 동작과 `2cce1a2`에서의 일치 여부를 Claude가 재확인한다.
- 위 내용은 조사 출발점이지 승인된 별도 규칙 문서가 아니다. 코드와 공유 안내가 다르면 양쪽 출처·SHA를 기록하고 임의로 정답 처리하지 않는다.

## 변경 금지 조건

- 게임 코드, 설정/경제, 실제 게임 규칙, UI/표시, 공용 테스트·시뮬레이터·프로토콜 및 공용 문서(TODO/DECISIONS 포함)를 수정하지 않는다.
- 분석 결과만으로 Monte Carlo 표본 수, 산식, 퍼센트 표시, 포상 또는 규칙을 바꾸지 않는다.
- R2 각 RUN의 보드-승자 확률과 2개 RUN 합산 승점/BB 기대값, 매치 단위 성공 확률은 서로 다른 지표로 취급하고 혼동하지 않는다.

## 지표와 완료 조건

- 코드 추적으로 계산식, 샘플 모집단, 표본 수, seed, 평가/타이 처리, 반올림, 결측 처리 및 UI의 지표 정의를 명시한다.
- 실제 R2 RUN별 주변 승률과 매치의 결합 결과(0-2, 1-1, 2-0 등)의 의미를 구분하고, 독립 산출물로 정량 비교한다. RUN 보드 비중복이 각 주변 확률과 결합 확률에 미치는 효과를 정확한 확률 논리로 설명한다.
- 전수 계산의 조합 수·연산량·실행 시간 가능성을 실제로 계산/측정한다. 전수 계산이 실용적이지 않으면 표본 방식의 절대 오차 또는 95% 구간, 대표 손 비교, 계산 시간·메모리와 화면 갱신 부담을 보고한다. 측정하지 않은 값을 성능 사실로 쓰지 않는다.
- 최소 20개의 고정된 서로 다른 R2 matchup 케이스를 다루거나, 수행 불가 시 실제 완료 개수와 사유를 보고한다. 각 케이스는 두 RUN의 카드 조합과 전체 6장 dead cards가 고정되어야 한다.
- 동일 카드 순서 재배열에서 재현성, 좌우 자리 교환에서 대칭성(동률 규칙 포함), 중복/불완전 카드 입력을 확인한다.
- 산식/표시의 오류·정확성에 대한 결론을 코드 근거와 실험 표본으로 뒷받침하고, 미확인 범위를 별도로 열거한다. 사용자 승인 없이 구현하지 않는다.
- REPORT에는 실행 명령, 커밋 SHA, 기준 커밋, seed/표본 설정, 입력 케이스 정의, raw 결과와 실패/제외 건수를 남긴다.
