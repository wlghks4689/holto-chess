# 카드 중심 Responsive UI Contract

기준: 2026-09-29 최신 One-Screen 재조정 지시. 기본 360×780, 추가 CSS 기준 402×874. 게임 규칙은 변경하지 않는다.

> PORENA의 주요 gameplay view는 360×780을 기준으로 page-level scrolling 없이 완전한 기능을 제공하며, 콘텐츠 증가 시 viewport를 확장하지 않고 UI density를 동적으로 조정한다.

## 공통 규칙

- `src/ui/responsive.css`가 화면별 카드 배치 규칙의 정본이다. 기존 파일은 색상·이미지·연출을 담당한다.
- 카드 비율은 53:75. 일반 카드와 작은 카드의 폭은 공통 CSS 변수와 `clamp()`로 정하고, 좁은 부모는 `min-width:0`으로 수축 가능하게 만든다.
- 카드 수 증가 시 가용 폭/슬롯 수로 자동 축소한다. 여백→gap→카드→보조 글자→컨테이너→정보 표현 순서로 압축하며 무조건 wrap하여 높이를 늘리지 않는다.
- 모바일 쇼다운: 1~4장 한 줄, 5장 중앙 정렬 3+2, 최종 7장 4+3. 5장의 두 번째 줄은 6개 반쪽 열 중 가운데 4칸을 사용한다. 실제 카드 순서와 BEST5/음영 클래스는 그대로 둔다.
- R4의5장3+2는540px 미만 쇼다운에만 적용한다.540px 이상 쇼다운과 모든 폭의R4 매칭 로딩은5장 한 줄이다. 매칭 로딩 스킬 아이콘은 닉네임 왼쪽이며 양쪽 동일 규격을 유지한다. 낮은 넓은 창은 수직 여백을 압축한다.
- R3 3인 타이브레이크는 모바일 프로필 가로3열을 유지한다. 각4장 카드의 폭은 해당 프로필 내부 가용 폭에서2px gap을 제외해 균등 분배하며 줄바꿈하지 않는다. 생존/탈락 스탬프는 프로필 위 예약 공간에 표시한다.
- 상점: 보유 슬롯 한 줄 균등 grid, 마켓 한 줄. R1만 두 슬롯을 중앙에 2px 간격으로 붙인다. 라운드 data-round로 범위를 제한하며 이후 라운드는 균등 grid를 유지한다. 가격/잠금/판매/리롤/준비 버튼까지 동시에 표시한다.
- 공개 포커 카드 드래프트: 모바일 8열×2행. 어빌리티 10슬롯은 5열×2행이다. 두 드래프트의 카드 수와 규칙을 혼동하지 않는다. 타이머는 제목/툴팁 옆의 예약된 헤더 공간에 표시한다. 타이머 유무가 제목 또는 보유 카드 위치를 밀지 않아야 한다.
- 순위표: 6열 HTML 표를 유지하고 8명 각각 한 줄. 긴 닉네임 ellipsis/title, 카드/전적/BB/점수를 축소한다.
- 최종 순위: 모바일 한 줄 행과 카드, BEST5 강조와 미사용/비공개 구분 유지. 생략된 점수 구성은 총점 버튼의 내역으로 확인한다.
- 매칭: 양쪽 프로필은 동일 grid/아이콘 크기/이름 영역이며 가용 화면 중앙에 위치한다. 공개된 상대 어빌리티도 같은 아이콘 컴포넌트로 표시하며 미배정만 fallback 사용. R4 3인 매칭은 동일 크기 2열+중앙 마지막 박스, 쇼다운은 3열 압축 프로필이다.
- 매칭 중앙의 기준은 새 전용 배경의 바닥 원이다.1024px 미만모바일/이상PC 이미지를 cover로 표시하고 동일57%/62% 기준점에 매칭 그룹 전체를 놓는다. RUN은 분할 박스 전체를 중심 정렬하며3인은 상단2명/하단1명을 원을 중심으로 균형 있게 배치한다. 제목과 하단 안내는 별도 고정 grid 행이다.
- 실제 쇼다운은 #root 바로 아래 렌더링한다. root의 flow-root로 외부 margin collapse를 차단한다. 콘텐츠 아래 여백이 많아도 body 최소 높이에 상단 margin이 더해져 스크롤이 생겨서는 안 된다.
- R2 RUN 2에서는 완료된 RUN 1 카드를 조금 줄이고 패배 카드에 약한 dim을 준다. 두 보드/스코어/보상/다음 진행 영역을 모두 높이 검사에 포함한다.
- 쇼다운 닉네임과 현재 순위는 행 gap 2px의 프로필 묶음으로 표시하고 카드와 별도 간격을 둔다. R1~R4 승리/패배는 하단 결과 영역 첫 줄, BB·승점은 둘째 줄. 연출 공개 시점은 유지하며 R5 최종 순위 스탬프는 보존한다.
- native dialog는 중앙 배치, 최대 90dvh와 내부 스크롤을 사용한다. 상세 창이 페이지 레이아웃을 밀지 않는다. 최종 점수 내역도 viewport 중앙의 제한된 영역에 표시한다.
- 콘텐츠 넘침을 overflow:hidden으로 은폐하지 않는다. 기존 카드 뒤집기/발광 연출의 마스크, 스크린리더용 표 머리글 숨김은 예외다.
- 기본 viewport의 주요 gameplay에서 `scrollHeight <= clientHeight`, `scrollWidth <= clientWidth`를 만족해야 한다. `100dvh` 및 헤더/하단 조작부를 포함한 높이 예산을 사용한다.
- 스크롤 예외는 사용자가 여는 secondary overlay의 긴 내용에만 적용한다. 모바일 매치 히스토리도 overlay로 펼쳐 배경 높이를 유지한다. 어빌리티 상세는 가용 높이에 맞춰 카드+닫기만 표시한다.

## 반복 검수

개발 서버의 `/responsive-preview`에서 실제 서비스 컴포넌트 69개 상태를 확인한다. 단일 fixture에 내비/헤더/하단 조작을 포함하며 쇼다운은 서비스처럼 root 바로 아래 렌더링한다. RUN 1 결과와 RUN 2 리버/완료, 보상/다음 진행 표시를 검수한다. 개발 빌드에만 경로가 등록되며 새 패키지는 없다.

1. 상태 선택에서 전체 또는 단일 화면 선택.
2. viewport 변경 후 카드 등장 애니메이션이 끝나면 `레이아웃 검사` 클릭.
3. 단일 상태 결과 JSON에서 pageVerticalOverflow, scrollHeight/clientHeight/viewportHeight, 문서 폭, 카드 그룹 겹침/이탈, 필수 버튼 viewport 이탈, 모바일 5장 3+2를 확인. 전체 매트릭스는 비교용으로 길어지므로 세로 합격 판정에 사용하지 않는다.
4. 단일 화면에서 팝업/긴 텍스트/발광/카드 앞뒷면을 육안으로 확인.

검사는 실제 DOM 치수 기반 보조 도구다. 미세한 글자 충돌, 효과 마스크, 애니메이션 중간 프레임과 실제 Safari 동작까지 자동 보증하지 않는다. 전체 매트릭스의 배경 `:has()` 영향은 단일 상태 검수로 보완한다.
