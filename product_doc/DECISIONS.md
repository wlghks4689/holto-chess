# 승인 결정과 변경 이력

## UI-SHOWDOWN-008 — 쇼다운 공개와 결과 표시

- 사용자 요청으로 보드 카드 공개 구간(FLOP 세 장·TURN·RIVER)과 R5 세 카드 묶음 공개 구간을 각 300ms 연장한다. 서버 공용 타임라인 버전을 10으로 올려 재접속 클라이언트의 길이 불일치를 감지한다.
- 리버 확인 지점은 튜토리얼 참조를 위해 유지한다. 족보 영역과 R5 제목/족보 DOM의 단계별 재생성을 줄이고, RESULT 시점에 승패와 보상을 함께 표시한다. R5 등수 보상은 해당 등수가 공개될 때 표시한다.
- 쇼다운 족보 아래 키커 문구는 PC/모바일 및 R4 3-way 예외 스타일에서 각각 1px 키운다. 게임 판정·보상 값은 변경하지 않는다.

## UI-R5-007 — 파이널 쇼다운 카드와 프로필

- 사용자 요청으로 R5 플레이어 2×2 배치를 유지하며 카드 7장은 PC/모바일 모두 한 줄로 배치한다. 박스 너비에 맞춰 카드 크기를 줄인다.
- 닉네임은 기존 프로필 영역에서 가운데 정렬하고, R5 현재 순위 배지는 제거한다. 공개된 최종 등수는 유지한다.

## UI-RESP-011 — 썸네일 이름과 닉네임 글꼴

- 사용자 후속 요청으로 썸네일 이름과 닉네임을 고딕 계열로 변경한다. UI-RESP-010의 썸네일 명조 결정은 이 요청으로 대체한다.
- 썸네일 이름은 높이 49~59% 영역에 한 줄로 배치하고 카드 너비 기준 9~13px로 축소한다. 모바일 상한은 12px다. 프레임 구분선과 겹치지 않도록 한다.
- 최종 사용자 요청: 닉네임 박스의 배경과 테두리는 제거한다. 닉네임 위치는 중앙 구분선과 하단 프레임 사이 중앙(높이 약 77%)을 유지하며, 고딕 글자와 가독성을 위한 그림자만 표시한다. 긴 닉네임은 한 줄 말줄임으로 유지한다.

## UI-RESP-010 — 공개 문구·글꼴 후속

- 제목은 “어빌리티 카드 확정”, 안내는 “카드를 선택하면 상세 효과를 볼 수 있습니다.”로 교체한다. 공개 화면의 `PORENA · ABILITY DRAFT` 보조 제목만 제거하며 공통 앱 헤더와 선택/순서 단계 보조 제목은 유지한다.
- 제목과 썸네일은 어빌리티 카드 이름의 명조 계열, 안내는 카드 효과 설명의 본문 글꼴을 사용한다. 기존 글꼴 색상을 유지한다. 두 줄 카드 이름과 닉네임 사이 여백을 확보한다.
- PC도 기존 공용 AbilityArtwork를 사용하므로 별도 구현을 추가하지 않는다. 프레임/아이콘 동시 공개 및 상세/썸네일 중심을 재확인한다. 게임 규칙, 타이머, 선택 슬롯 수, 공개 범위는 변경하지 않는다.

## UI-RESP-009 — 어빌리티 이미지 동시 공개와 아이콘 규격

- 프레임과 아이콘을 함께 decode한 후 하나의 visibility 상태로 공개한다. 순서 단계에서 미리 준비하고 중복 요청을 공유한다. 상세와 썸네일 모두 아이콘 중심 (50%, 30.8%), 영역 너비 54%·높이 36%를 사용한다.
- 아키텍트는 첫 생성한 은색 3탑·청보라 메달을 사용한다. 왕가의 혈통은 사용자 후속 지시에 따라 기존 은색 왕관·남색/청색 바탕·붉은 보석 분위기로 재제작한다. 이전 SVG는 삭제하지 않는다.
- 768px 이하에서만 4열 × 3행을 사용한다. 서버의 선택 슬롯 10개 및 랜덤 배정은 유지하고 마지막 2칸은 비활성 장식이다. PC는 5열 × 2행을 유지하며 짧은 높이에서는 카드 영역과 여백만 줄인다.
- 이번 변경은 로컬 구현/검수 범위이며 자동 커밋·푸시·운영 배포하지 않는다.

## UI-RESP-008 — 매칭 아트워크·전장 중심 구도

- 사용자 Downloads의 모바일/PC PNG를 수정 없이 `public/assets/table/match-arena-mobile.png`, `match-arena-pc.png`로 등록한다. CSS viewport1024px 이상만PC 이미지를 사용한다. 다른 게임 페이즈의 배경은 유지한다.
- 매칭의 제목·하단 안내를 제외한 남은 공간 중앙 대신, 새 배경 바닥 원의 기준점을 매칭 그룹 전체의 중심으로 사용한다. 이미지 cover 크롭과 프로필 배치에 같은 기준점(모바일57%,PC62%)을 적용한다.
- RUN1/2를 포함한 두 프로필은 동일 중심/같은 높이.3인은 전체 그룹 중심을 유지하며 위쪽2명/아래쪽1명의 좌석을 대칭 배치한다. VS는 작은 중앙 표시로 프로필 내용을 가리지 않게 한다.
- 낮은 넓은 화면의4인R5는7장 한 줄로 압축해 제목/하단 안내 겹침을 피한다. 게임 데이터/판정/규칙/보상 변경 없음. [QA](qa/2026-09-29-match-background.md).

## UI-RESP-007 — R4 3+2는 좁은 쇼다운 한정

- 최신 사용자 지시가 이전5장 모바일 공통3+2 정책을 구체화한다. R4 매칭 로딩의5장은 항상 한 줄, 스킬 아이콘은 닉네임 왼쪽. 양쪽 동일 크기와 중앙 배치는 유지한다.
- R4 쇼다운은 CSS viewport540px 미만에서만3+2,540px 이상은5장 한 줄. 2인/3인 모두 적용하고 카드폭을 해당 프로필 가용 폭에 맞춘다.
- 540px 이상·높이800px 이하에서는 제목/좌석/족보/하단 여백을 조금 줄여 낮은 창에서도 주요 결과를 한 화면에 표시한다. 게임 규칙/판정/보상은 변경하지 않는다.
- 실제 DOM 기반 QA도 매칭과 쇼다운의 기대 행을 분리했다. [검수](qa/2026-09-29-r4-layout.md).

## UI-RESP-006 — R3 3인 타이브레이크 가로 배치

- 사용자 첨부 SURVIVAL SHOWDOWN은 R3 타이브레이크3인 화면이다. 기존 모바일 다인 기본1열 규칙에서 R4만 예외여서 세로 스크롤이 발생했다.
- R3 참여자3명에만 전용 배치 클래스를 적용하고 모바일 세 프로필을 가로3열, 각4장 카드도 한 줄로 표시한다. 작은 프로필 폭에 맞춰 카드 외곽을 자동 축소하고 생존/탈락 스탬프 공간을 확보한다.
- R3 2인, R4 5장3+2, R5 배치를 보존하며 게임의 타이브레이크 규칙과 판정은 변경하지 않는다. [QA](qa/2026-09-29-r3-threeway.md).

## UI-RESP-005 — 프로필과 승패·보상 분리

- 승리/패배는 모든 해당 쇼다운(R1~R4, RUN 결과 포함)의 하단 보상 영역 첫 줄, 기존 BB·승점은 둘째 줄로 표시한다. 공개 타이밍/승패 판정/보상 값은 유지한다. R5의 기존 최종 순위 스탬프는 별개로 보존한다.
- 최신 후속 지시가 순위와 닉네임 사이의 큰 간격 요청을 대체한다. 닉네임 바로 아래 순위를 붙여 한 묶음으로 만들고 카드와의 간격을 분리한다. 총 높이는 늘리지 않는다.
- R3 플레이어 카드 내부 랭크·문양만 이전 수정보다 각각 추가1px. 커뮤니티 보드와의 내부 글꼴 통일은 가능 여부 문의이며 아직 적용하지 않는다.
- 검증 범위와 글꼴 실측: [QA](qa/2026-09-29-showdown-result-footer.md).
