# QUAD CORE 구현 및 검증

## 승인 범위

- 사용자 제공 신규 어빌리티 문서 및 “좋습니다 해당 스킬 아이콘으로 확정하고 진행하세요” 승인.
- 승인한 v3 PNG 그대로 등록. 왕관·랭크 없는 2×2 네 카드와 붉은 테두리/후광.
- 로컬 구현. 이번 기능의 커밋·push·운영 배포는 아직 실행하지 않음.

## 구현

- 판정: src/game/abilities.ts의 quadCorePlacementBonus. R5 / QUADS / 보유 중인 정확한 firstCardId / BEST5 포함 / QUADS kicker rank 일치.
- 정산: engine.ts의 rewardFinalPlacements → rewardQuadCorePlacement → rewardAbilities → interest → reward ledger/final standings.
- 순위 기본값 20/12/5/3에 보너스 20/12/5/3을 더함. ICM은 먼저 확정한 본인 배분액만 추가 지급. 다른 참가자 배분액, 누적 승점, BB, 족보 점수는 변경하지 않음.
- reason=r5-quad-core. abilityEvents 및 abilityTotals에 추가분만 기록. 같은 매치 중복 보너스 방지.
- ABILITY_IDS를 서버/클라이언트 공통 정본으로 사용. 입력 프로토콜의 기존 slot≤9 제한도 공통 길이로 교체.
- 뷰에 실제 덱 slotCount 전달: 이전 10종 진행 게임은 유지, 신규 게임은 11종 중 8명 선택/3종 미선택.
- 모바일 4×3(선택 11+장식 1), PC 6열×2행. 한·영 카드 설명 및 상세 조건 접기/펼치기 추가.
- 기존 artwork decode barrier 및 썸네일/상세 공통 정렬 재사용.

## 검증

- 신규 quadCore.test.ts: 25개. R1–R4 미발동, 정확한 카드/키커/판매 후 부재/재획득, 풀하우스·스트레이트 플러시·로열 플러시 제외, 기존 10종 미변경, 1~4위 보너스, 중복 정산, ICM 배분 후 보너스, 11번째 프로토콜 입력/자동 선택/직렬화 복원/최초 카드 발급.
- ICM 테스트의 동률 포카드는 방어적 합성 fixture: 현재 공용52장·보드 없는 R5에서는 같은 포카드 동률 자체가 자연 발생하지 않는다. 게임 규칙을 바꾸지 않았다.
- 전체 unit suite 최종 실행 75파일/519테스트 통과(123.29초).
- Cloudflare Worker 실제 런타임 13/13 통과(두 WebSocket, R1–R5, 저장·재접속·중복 요청·alarm 등).
- 클라이언트 tsc -b, Worker tsc -p tsconfig.worker.json 통과. Wrangler 타입 생성 및 Vite client/Worker 빌드 통과.
- 변경 TS/TSX lint 통과. 전체 lint는 기존 OnlineApp.tsx:94의 react-hooks/set-state-in-effect 1건 실패. 원본 git checkout과 해당 파일 해시 동일함을 확인했으며 이번 범위 밖이라 수정하지 않음.
- 실제 개발 브라우저 360×780 / 402×874 / 1280×900: 페이지 세로/가로 넘침 0, 11개 버튼, 모바일 장식1개, PC6열. 쿼드 코어 모달 열기/닫기/재열기, 상세 조건 펼치기 검증. 360px 상세 조건 높이/scrollHeight 299/299, 모달 544/544.
- 승인 이미지와 배포용 파일 SHA256 동일 복사.
- 11종 갤러리 및 영어 전환, QUAD CORE 영문 상세 렌더링 확인 후 한국어·뷰포트 원복. 구현 화면: output/imagegen/quad-core-implemented-mobile.png (작업 공간).
