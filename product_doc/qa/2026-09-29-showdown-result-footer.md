# 쇼다운 프로필·결과 영역 QA — 2026-09-29

## 원인과 수정

프로필에 닉네임·현재 순위·승패를 좁은 고정 행으로 모두 쌓아 카드와 가까워지고 정보 우선순위가 섞였다. 승패를 공통 하단 결과 영역으로 이동해 첫 줄에 표시하고 BB·승점은 둘째 줄에 유지했다. 닉네임과 순위는 최신 지시에 따라 행 간격2px로 묶고, 모바일 카드와의 외부 여백은12px로 분리했다. 기존 대비 총 높이는 유지한다.

R3 플레이어 카드 랭크·문양을 직전 수정보다 추가1px 확대했다. 카드 외곽 크기 및 보드 글꼴은 변경하지 않았다. 결과 공개 플래그, 게임 상태, 승패 판정, 보상 값은 변경하지 않았다. R5의 최종 등수 스탬프는 유지했다.

## 글꼴 실측과 문의 답변

375×811 실제 R3에서 커뮤니티 보드 랭크16.2641px/문양21.8403px, 플레이어 카드 랭크12.54px/문양15.64px. 공통 compact 글꼴은 랭크 `clamp(12px,35cqw,20px)`, 문양 `clamp(16px,47cqw,26px)`로 카드 내부 가용 폭에 비례한다. R3 모바일에는 별도 확대 규칙이 적용된다.

카드 외곽 치수와 내부 font-size는 독립적으로 설정할 수 있다. 전체 라운드에 보드 글꼴을 그대로 적용하면5장/7장의 좁은 카드에서 과밀해질 수 있다. 이번 요청은 가능 여부 문의이므로 보드와 플레이어의 글꼴 통일은 추가 적용하지 않았다.

## 2026-10-13 후속 검수 — R1 족보 위치·R2/R5 RUN 상세 카드

사용자 요청: R1 족보를 내 카드와 하단 테두리 사이의 가운데로 옮기고, 완료된 R2/R5 RUN 상세 카드의 랭크·문양을 카드 크기에 맞게 확대한다. 기준 checkout은 `main`의 `0707ed3`. 소스 변경은 `holto-chess/src/ui/six-round.css`에 한정했으며 판정·보상·공개 시점·재생 타임라인과 상세보기 클릭/호버 동작은 변경하지 않았다. 구현·검수 후 사용자가 이번 수정의 `main` 커밋·푸시를 승인했다. 수동 Worker 배포는 실행하지 않으며, 푸시로 시작되는 자동 빌드 상태는 별도로 확인한다.

### 원인과 보정

- PC R1은 홀카드 행의 `flex:1`이 여백을 모두 차지해 족보가 패널 바닥으로 밀렸다. 카드 영역과 아래 읽기 영역을 3:2로 나누고 족보를 아래 영역의 가운데에 배치했다. 패널 하단 padding의 절반을 보정해 카드 하단과 외곽 테두리 사이 중간점에 맞춘다. 결과 footer는 이 flex 계산에서 제외해 결과 공개 때문에 족보·카드가 이동하지 않도록 했다.
- 낮은 PC 창에서는 족보/키커와 승패/보상이 겹치지 않게 R1 footer 간격을 줄이고 프레임 최소 높이 640px을 확보했다. 높이가 부족하면 세로 스크롤을 허용한다. 모바일의 기존 좌석 배치는 유지한다.
- RUN 상세는 공통 30px, R2 25px, 모바일 25px, PC RUN 상자 높이 기반 계산이 서로 경쟁했다. 글자는 별도의 10/12/14px 규칙을 사용했고, glow 카드는 1.025배 커져 다른 카드와 외곽 크기도 달랐다.
- 공통 `--run-detail-card-width`에서 카드 높이(53:75), 랭크(폭의 44%), 문양(폭의 58%), 카드 간격과 두 줄짜리 상세 상자 높이를 계산한다. 상세 카드의 scale은 제거하되 glow·dim 색상은 유지한다. PC 완료 RUN은 같은 높이를 예약하고, 상세 상자는 명시적인 공통 높이를 사용해 RUN 경계선의 1px 차이도 내부 규격에 영향을 주지 않게 했다.
