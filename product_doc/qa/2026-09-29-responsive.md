# 전체 카드 UI 반응형 QA

> 역사적 기록: 이 문서의 모바일 세로 스크롤 허용 정책은 최신 [One-Screen 계약](../RESPONSIVE_UI_CONTRACT.md) 및 [재검증](2026-09-29-one-screen.md)으로 대체되었다.

## 원인과 변경

| 영역 | 원인 | 변경 |
|---|---|---|
| 상점 | 고정 라벨 열, nowrap 목록, 카드 위 절대배치 구매 버튼 | 좁은 화면 단일 열, 카드 wrap, 독립 버튼 행 |
| R4 쇼다운 | 헤즈업 5장 한 줄 축소, 3인 모바일 3열 프로필 | 5장 3+2, 3인 프로필 2열+중앙 1개 |
| 순위표 | 6열 표에 긴 이름·큰 수치·최대 카드 동시 압축 | 모바일 행 grid, 이름/카드/수치 영역 분리 |
| 공개 드래프트 | 모바일 8열 카드, 이름·BB·상태 한 줄 경쟁 | 모바일 4열, 선택 순서 2줄, 타이머 분리 |
| 최종 결과 | 7장 한 줄 축소, 마지막 행 내역창 화면 이탈 가능 | wrap 및 중앙 내역창 |
| 상세 창 | 화면 높이를 고려하지 않은 내용 높이 | 최대90dvh 내부 스크롤 |

## 재현 범위

- R1~R5 각각 카드 0장/중간/최대 상태의 상점·매치 대기·쇼다운. 실제 최대치는 2/3/4/5/7장.
- 라운드별 8명 순위표, 긴 영문 무공백 이름, 한글 이름, 123456.75BB, 98765점, 탈락자 및 비공개 카드.
- Ability 선택 순서/0명/1명/4명/8명, 내 상세/상대 상세.
- R2/R4 공개 드래프트와 선택 중 타이머, RUN 배치, 2게임 배치, R4 헤즈업, 브래킷, 최종 순위.
- 개발 fixture는 UI 재현용이다. 인위적으로 큰 수치와 카드 수를 넣고 서버 액션을 보내지 않는다. 판정 정확성은 fixture 승패가 아니라 기존 테스트가 담당한다.

## 상호작용·시각 확인

- 360px R4 헤즈업/3인 카드 3+2, 카드 앞면 및 승자 발광/패자 음영 유지.
- 360px 상점 5장과 가격·잠금·판매 버튼, 공개 드래프트 16장, 순위표/최종 7장.
- PC 1280px 순위표.
- 360×560 어빌리티 상세: x12~348, y28~532, 높이504(90dvh), 내부 스크롤. 닫기 후 상대 타겟 스나이퍼 재열기 정상.
- 402×874 판매 확인창: x23.6~363.6, y362.9~511.5. Escape 닫기.
- 402×874 순위 상세: x4.4~382.8, y107~767.4, 숫자 셀 가로 넘침0.
- 총점 버튼 내역 열기 확인. 내역창은 마지막 행에서도 화면 중앙을 사용한다.

## 검증 및 범위 제한

- UI 31개 테스트 파일 / 188개 테스트 통과. 추가 data-count 속성에 맞춰 기존 마크업 검사를 갱신하고 5장 표시 보존 테스트를 추가했다.
- TypeScript 앱/Worker 및 수정 TS 파일 ESLint 통과. Vite client/Worker 생산 빌드 성공. 초기 Wrangler 로그 EPERM은 로그 경로를 임시 폴더로 지정한 최종 빌드에서 해소했으며 client/Worker 산출물 및 종료코드0 확인.
- 작업 전후 `src/game`, `src/core`, `src/shared`, `worker` 전체 파일 SHA256 동일. 서버 이벤트/가격/판정/어빌리티 효과 변경 없음.
- 전체 테스트 최초 병렬 실행은 장기 게임 시뮬레이션들이 30초 제한을 초과해 중단했다. `node node_modules/vitest/vitest.mjs run --maxWorkers=2 --testTimeout=120000` 재실행은 **73파일/487테스트 전부 통과**, 종료코드0, 소요521.84초. 동일한 제한 병렬 설정의 UI 범위는 31파일/188테스트, 약52초에 통과했다.
- 실제 iPhone Safari 실기기, 터치 하드웨어, 다중 온라인 클라이언트의 전체 경기 완주는 이번 검증에 포함하지 않았다. 동기화 코드도 변경하지 않았다.
- 운영 배포·push 없음. 개발 서버 반영.
